# BT Mouse v1.4.2

## Off-Network Remote Access Over a Cloudflare Quick Tunnel

This release adds Phase 1 of the unified connectivity plan: reaching your PC from
outside its network without a domain, a paid relay, or exposing control to the public.
The companion runs a cloudflared quick tunnel in front of the WebSocket server and
publishes its current address — signed — to a tiny Cloudflare Worker you host. The
phone resolves that record, verifies the signature, and connects. Because the tunnel
URL is looked up live, a tunnel restart no longer means re-scanning a QR.

- **Signed rendezvous Worker (`cloudflare-rendezvous/`)**:
  - A small Cloudflare Worker + KV stores one Ed25519-signed address record per PC.
  - Every `PUT` is signature-checked, and each record id is bound to the first key that
    signs it (trust-on-first-use), so learning the id is not enough to overwrite it.
  - Records self-expire after 24 hours; `README.md` has the one-time `wrangler` deploy steps.

- **Tunnel manager and identity on the PC (`pc_server/remote_tunnel.py`, `app_gui.py`)**:
  - A stable Ed25519 identity is kept in `remote.json`; its public half rides in the QR,
    its private half signs each published record.
  - The companion starts and auto-restarts cloudflared, parses the public URL, and keeps
    the signed record fresh.
  - The Remote access page gains a Worker-URL field, a **Turn on internet access** toggle
    with live status, and an `rv` block in the WAN QR. Same QR, same PIN as before.

- **Automatic address resolution on Android (`RemoteRendezvousResolver.kt`, `ConnectionScreen.kt`, `ConnectionCoordinator.kt`, `SettingsRepository.kt`)**:
  - The phone fetches the record, verifies it with Tink Ed25519, rejects anything older
    than 10 minutes or tampered, and connects to the live `wss://` address.
  - QR pairing and auto-reconnect resolve the current URL first and fall back to the saved
    local address when on the same network.

- **Dependencies and packaging (`requirements.txt`, `BT-Mouse-Companion.spec`, `build.gradle.kts`)**:
  - Adds `pynacl` (PC) and Google Tink (Android). The PyInstaller spec bundles `nacl` and,
    when present next to the spec, `cloudflared.exe`.

- **Tests (`pc_server/test_server.py`)**:
  - New checks cover the record-id stability, Worker-URL persistence, the cloudflared URL
    parse, and a signed-record round-trip with tamper rejection (crypto test skips cleanly
    where PyNaCl is absent, so the dependency-free regression step stays green).

## Compatibility and Versioning

- Android app version: 1.4.2 (version code 26).
- Windows companion and server protocol version: 1.4.2.
- Off-network access is opt-in: it does nothing until you deploy the Worker and paste its
  URL into the companion. Local Wi-Fi, Bluetooth and Tailscale paths are unchanged.
