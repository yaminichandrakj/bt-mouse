# BT Mouse v1.3.9

This release restores reliability after the v1.3.8 feature expansion, especially for basic input, live status, and camera sessions.

## What's new and fixed

- **Keep mouse and keyboard responsive:** media-session queries and controls now run away from the network command loop. Camera startup, snapshots, and live-audio start/stop work also run outside the input and WebSocket event loops.
- **Keep Wi-Fi and WAN sessions alive:** Wi-Fi now waits 30 seconds without a pong before declaring the PC disconnected, and its heartbeat no longer competes with media polling. Camera stream leases also tolerate transient delays up to 30 seconds. WAN keepalives no longer trigger extra media queries.
- **Prevent WebSocket camera backlog:** only one camera frame send can be pending per client, so a slow link drops stale frames instead of accumulating a queue.
- **Show the correct media state:** corrected Windows Playing/Paused values and preserve the last known track across transient Windows media-session errors, avoiding reversed controls and flickering status.
- **Identify the player consistently:** the media screen always shows a stable player badge when Windows or browser-session data identifies YouTube, Netflix, Spotify, VLC, and supported browsers. It no longer relies on album-art retrieval for the player identity.
- **Keep Pen and touch disabled:** the navigation entry remains disabled with an explanation while the feature is rebuilt; mouse and keyboard remain available.
- **Keep media polling separate from connection health:** media status is requested by the media screen rather than being mixed into transport heartbeat traffic.
