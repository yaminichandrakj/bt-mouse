# BT Mouse v1.4.3

## One Connect Screen, One QR, Working Updates and Reliable Internet Access

- **One pairing QR for every connection (`pc_server/app_gui.py`)**:
  - The companion's Wi-Fi, Bluetooth and Remote access pages are now one **Pair a device**
    page with a single QR. It carries the PC name, local address, both ports, the PIN and the
    internet lookup details.
  - Internet access remembers it was turned on and starts again by itself after a reboot or
    an update, so the PC stays reachable while you're away.

- **One Connect screen on the phone (`ConnectionScreen.kt`, `ConnectionCoordinator.kt`, `SettingsRepository.kt`)**:
  - The Bluetooth, Wi-Fi and Remote WAN tabs are replaced by one screen. Scan once and the app
    saves the PC and connects over Wi-Fi, Bluetooth and the internet together, using whichever
    is fastest. Chips show each link as On, Slow or Off.
  - Links that drop come back by themselves (checked every 30 seconds while connected).
  - Bluetooth connects only to the paired PC — matched by the device you tap once, or by name —
    never just the first paired device (such as earbuds).
  - Changing the PIN on the PC only needs the new PIN on the phone, not a new scan.
  - The **Automatic Measured Failover** switch is removed from Settings: links are always chosen
    automatically now.

- **Internet publishing retries quickly (`pc_server/remote_tunnel.py`)**:
  - A single timed-out connection to the Worker no longer leaves the phone without an address for
    four minutes: the companion retries after 5 seconds, backing off to 60, and says when the
    address is published.

- **In-app companion updates now install (`pc_server/update_script.py`, `app_gui.py`)**:
  - Clicking **Download update** closed the companion, but the swap failed straight away with
    "file in use" and the old version stayed. A one-file EXE runs as a launcher plus the app,
    and the swap script only waited for the app while the launcher still held the EXE open.
  - The swap now waits for both processes, retries while the file is locked, gives a slow
    first start up to 90 seconds, and keeps a new version that is still starting instead of
    rolling it back. Every step is written to `%TEMP%\btmouse-update.log`.
  - A progress window shows the download in MB with a Cancel button, then says the companion
    is installing and will reopen by itself.
  - **Install v1.4.3 manually once.** v1.4.2's own updater still uses the old swap script, so
    update by downloading `BT-Mouse-Companion.exe` from this release. Later updates work in-app.

- **Publishing no longer blocked by Cloudflare (`pc_server/remote_tunnel.py`)**:
  - The companion's address publish was rejected with HTTP 403 before reaching the Worker:
    Cloudflare answers Python's default `Python-urllib` User-Agent with error 1010. The
    companion now identifies itself as `BTMouse-Companion`, so the signed record is stored
    and the phone can resolve the tunnel address from mobile data.
  - A rejected publish now shows what the Worker or Cloudflare actually returned, instead of
    a generic "check the Worker URL".

- **Clearer phone feedback (`ConnectionScreen.kt`)**:
  - When the internet lookup fails, the phone now says why (for example "PC is offline") before
    falling back to the local Wi-Fi address, instead of failing silently on `ws://` addresses
    that only work on the PC's own network.

- **Tests (`pc_server/test_server.py`)**:
  - New regression check that the publish request is a `PUT` with the named User-Agent.
  - New checks that the update script waits for every process holding the EXE, retries the
    locked move, keeps a slow-starting version, and logs each step.

## Compatibility and Versioning

- Android app version: 1.4.3 (version code 27).
- Windows companion and server protocol version: 1.4.3.
- Update both the phone app and the companion, then scan the new QR once from the Connect
  screen. Your Worker URL and PC identity carry over; after this scan only PIN changes are needed.
